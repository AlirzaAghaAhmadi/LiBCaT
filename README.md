# LiBCaT — Breast Cancer Clinical Trial Retrieval

![Python](https://img.shields.io/badge/python-3.10%2B-blue)
![Research](https://img.shields.io/badge/status-research_prototype-orange)
![License](https://img.shields.io/badge/license-MIT-lightgrey)

**LiBCaT** is an experimental Python toolkit for exploring retrieval and reranking of
potentially relevant *breast-cancer clinical trials* from structured patient descriptions.
It brings established information-retrieval methods and publicly available pretrained
models into one research workflow, with a reusable Python API, a Streamlit demo, and
TREC Clinical Trials 2023 evaluation scripts. **It does not introduce or claim a new
trained foundation model, a clinically validated matching system, or benchmark superiority.**

> **Research only.** A retrieval result is not an eligibility decision, diagnosis,
> treatment recommendation, or clinically validated patient-matching outcome. Clinical
> teams must verify criteria and trial status independently. Never use real identifiable
> patient information in a public demo.

## What is included?

- **Lexical baseline:** field-aware BM25 plus heuristic clinical compatibility/contradiction signals.
- **Optional local models:** MiniLM sentence embeddings, general cross-encoder and NCBI MedCPT reranking.
- **Demo app:** a structured query form and ranked study cards; defaults to a tiny *synthetic* trial table.
- **Evaluation:** 2023 breast-cancer topics, graded TREC qrels (`0=not relevant`, `1=excluded`, `2=eligible`), nDCG@10 and eligible-only retrieval metrics.
- **Reusable code:** install package as `libcat-retrieval`, import Python API as `libcat`.

**No hosted LLM or commercial API key is needed for retrieval.** Optional pretrained
models are downloaded locally on first use; the current ClinicalTrials.gov API is used
only when you explicitly build a demo snapshot.

## Current status (v0.1.0)

This is an **early research/software prototype**, not a validated scientific result or
production clinical product. Here is what the repository actually provides today:

| Available in this repository | Not established or not yet included |
| --- | --- |
| A runnable lexical/BM25 retrieval baseline and heuristic clinical-term matching | A newly trained language model or novel retrieval algorithm |
| Optional integration with existing MiniLM/MedCPT pretrained models | Evidence that any configuration outperforms published baselines |
| A synthetic-data Streamlit demo and Python usage example | Real-patient matching or automated eligibility decisions |
| Unit tests and a small synthetic TREC evaluation check | Full-data and heavy-neural checks in automated CI |
| Scripts for historical TREC ingestion and scoring | A fully reproduced, independently verified benchmark result |

The default offline flow can be tested without downloading the historical corpus.
The latest **recorded** research experiment results are reported below, along with
reproducibility limits. See [limitations](#reproducibility-and-limitations) and the
[development roadmap](ROADMAP.md).

## Latest recorded experimental results — TREC Clinical Trials 2023

The following is the **most recent three-variant comparison available in the
project's retained experiment files**. It evaluated **12,249 candidate trials**
for **5 breast-cancer topics** (topic IDs 16–20) from the TREC 2023 track.
These are *reported research-run results*, not measurements of the Streamlit demo,
and not newly rerun by the current repository's CI.

| Retrieval / reranking variant | Recorded nDCG@10 | Eligible Hit@5 | Eligible P@10 | Eligible MRR |
| --- | ---: | ---: | ---: | ---: |
| Hybrid (v4 baseline) | 0.3359 | 60% | 20% | 0.5274 |
| MedCPT rerank only | 0.3347 | **80%** | 20% | 0.5051 |
| Hybrid + MedCPT score fusion (55% / 45%) | **0.3547** | 60% | 20% | 0.5274 |

All three rows use the same documented evaluation scope, and the archived
**Eligible Qrel Coverage** was **96.82%**. *Eligible Hit@5* is the fraction of
topics with at least one eligible-labeled study in the first five results; these
labels are TREC assessments rather than clinical eligibility decisions.
On this small sample, fusion had the highest **recorded** nDCG@10; MedCPT-only
had the highest Eligible Hit@5. No statistical or generalization claim is made.

**Metric-version notice:** The recorded nDCG values were generated by the
original evaluation implementation. The `libcat.trec` implementation was later
corrected to use *linear* TREC 2023 gains (0, 1, 2). Thus, the displayed nDCG
values are **not verified under the current metric definition** and should not
be compared directly with newly generated scores. A full-corpus rerun with
version-pinned models and data is a planned reproducibility task.

**Source:** [archived comparison JSON](experiments/original_results/trec_medcpt_comparison.json),
[per-topic CSVs and provenance note](experiments/original_results/README.md).
The values above were checked against those per-topic records. A separate
`nDCG@10 = 0.4042` figure discussed during earlier experimentation is **not**
part of these retained outputs and is therefore **not reported as a verified
repository result**.

## Quick start — offline lexical mode

If you downloaded the ZIP, extract it and run these commands from the `LiBCaT/`
folder. Requirements: Python **3.10+** (Linux, macOS or Windows) and an internet connection
*once* to install Python dependencies. No large datasets or model weights needed.

```bash
python -m venv .venv
source .venv/bin/activate   # Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python scripts/smoke_test.py
python scripts/check_env.py     # local dependencies and data inventory
streamlit run app.py
```

To use `pytest` instead, install the development extra with `python -m pip install -e ".[dev]"`.

Choose **Lexical (offline)** in the sidebar. The eight `SYNTH*` study IDs are fake
fixtures, not real study records. See `examples/custom_corpus.py` for Python API use.

## Real ClinicalTrials.gov demo snapshot

```bash
python scripts/build_demo_snapshot.py --max-studies 200  # quick API check
# or: python scripts/build_demo_snapshot.py             # full US breast-cancer snapshot
streamlit run app.py
```

The app loads `data/demo_trials.csv` when present; otherwise it loads the synthetic
sample. Snapshot scoping happens at acquisition (US, interventional, recruiting and
not-yet-recruiting). The runtime retriever does *not* apply patient eligibility filters.
The current demo snapshot must not be mixed with 2023 TREC qrels.

## Optional neural retrieval and biomedical reranking

```bash
python -m pip install -r requirements-dense.txt
streamlit run app.py  # select Hybrid or Biomedical rerank in the sidebar
```

- `Hybrid`: BM25 + dense embeddings + general MiniLM cross-encoder and clinical signals.
- `Biomedical rerank`: runs the hybrid retriever then reranks its top ten with
  `ncbi/MedCPT-Cross-Encoder` (an optional local biomedical model).
- The 55/45 v4/MedCPT experiment is available in
  `scripts/run_medcpt_rerank_eval.py`; it is an **evaluation experiment**, not the
  same as the app's pure MedCPT top-ten reranking display.

Neural dependencies and model weights are large; first-time use needs network access.
The synthetic data and offline lexical tests do not require them.

**Explicit optional-model verification** (not part of CI because it downloads large
weights and can require substantial memory):

```bash
python scripts/verify_optional_models.py --mode hybrid
python scripts/verify_optional_models.py --mode biomedical
```

These commands fail if the required models or reranking stages do not load. The
Streamlit Hybrid UI marks the missing general cross-encoder rather than claiming
that the full pipeline ran. Biomedical mode requires both the general hybrid
cross-encoder and MedCPT; it does not silently fall back to a simpler pipeline.
**Passing the offline test suite does not verify neural retrieval or MedCPT.**

## TREC Clinical Trials 2023 evaluation (historical dataset)

Official metadata/collection: [TREC 2023 Clinical Trials track](https://trec.nist.gov/data/trials2023.html).
The historical May 8, 2023 collection contains **six large ZIP archives (~2 GB total)**.
Keep them outside Git history in the ignored `data/trec/` directory:

```bash
python scripts/download_trec_data.py --corpus   # also downloads topics/qrels
python scripts/parse_trec_corpus.py            # all 6 ZIPs required
python scripts/run_trec_eval.py --mode lexical
# Optional: python scripts/run_trec_eval.py --mode hybrid
# Optional: python scripts/run_medcpt_rerank_eval.py
```

Already have the 2–3 GB archives? Put them in `data/trec/` and run
`python scripts/download_trec_data.py` for missing topics/qrels. See
**[large data guide](docs/data-management.md)** for paths and redistribution rules.

The evaluation reports `nDCG@10`, `EligibleHit@5`, `EligibleP@10`,
`EligibleRecall@10`, `EligibleMRR` and `EligibleQrelCoverage`. `nDCG@10` uses the official
TREC 2023 linear gains (0, 1, 2), **not** exponential gains. All grades are
from qrels, not predictions of real clinical eligibility. **Recompute benchmarks on
the full historical candidate set; check coverage before reporting results.**
Archived outputs from the supplied prototype are retained under
`experiments/original_results/` as historical artifacts. They have not been
recomputed with the corrected linear-gain nDCG implementation, so do **not**
compare their nDCG numbers directly with fresh evaluation output.

## Developer workflow

LiBCaT is intended to be **reused as a Python package** and improved through small,
reviewable Pull Requests. **You do not need the multi-GB TREC dataset to begin.**
The default test suite runs against synthetic fixtures and does not download neural
models. Use the [contributor checklist](CONTRIBUTING.md) for review expectations.

### 1. Get the code and install developer dependencies

After the repository is published, clone it (replace `OWNER` with the repository owner):

```bash
git clone https://github.com/OWNER/LiBCaT.git
cd LiBCaT
python3 -m venv .venv
source .venv/bin/activate      # Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -e ".[dev,web]"
```

On restricted or unreliable networks, build-isolation downloads may fail while
`setuptools` is already installed in the active environment. If you see errors
about fetching `setuptools>=68`, first install `setuptools` and `wheel`, then use:

```bash
python -m pip install --no-build-isolation --timeout 180 --retries 10 -e ".[dev,web]"
```

This is a troubleshooting option rather than the default; it requires build
tools to be present locally. See [pip build isolation](https://pip.pypa.io/en/stable/reference/build-system/).

If you have **write access as a collaborator**, clone the main repository. Otherwise,
**Fork** it on GitHub and clone your own fork, then send changes upstream as a PR.
The `-e` editable install makes changes in `libcat/` immediately importable without
reinstalling the package. Neural dependencies are intentionally optional.

### 2. Run the fast baseline before making changes

```bash
python -m pytest -q
python scripts/smoke_test.py
python examples/custom_corpus.py
python scripts/run_trec_eval.py --mode lexical \
  --trials tests/fixtures/mini_trials.csv \
  --topics tests/fixtures/mini_topics.xml \
  --qrels tests/fixtures/mini_qrels.txt \
  --output-dir results/dev-fixture
streamlit run app.py              # select Lexical (offline)
```

The TREC command above is a **small integration check**, not a full benchmark.
It writes outputs under ignored `results/`. If these commands fail, please open an
Issue with your Python version, command, stack trace, and a reproducible synthetic
example (never include real patient information).

### 3. Know where to make a change

| Goal | Start here | Minimum validation |
| --- | --- | --- |
| Add or modify BM25/dense retrieval, ranking or score fusion | `libcat/retrieval.py` | `tests/test_retrieval.py` + smoke test |
| Change clinical query concepts, aliases or query construction | `libcat/text_utils.py` | Add a focused unit test in `tests/` |
| Change MedCPT reranking | `libcat/medcpt.py`, `scripts/run_medcpt_rerank_eval.py` | Synthetic tests first; optional model evaluation separately |
| Add trial acquisition or transformations | `libcat/clinicaltrials.py`, `scripts/` | `tests/test_data_parsers.py` |
| Add TREC metrics or modify evaluation | `libcat/trec.py`, `scripts/run_trec_eval.py` | `tests/test_metrics.py` + synthetic integration command |
| Improve the user interface | `app.py` | Keep Lexical (offline) usable; launch Streamlit locally |
| Use an external corpus | `examples/custom_corpus.py`, `docs/integrate-your-data.md` | Verify the required columns and run a smoke search |

To import LiBCaT from another project, use `from libcat import TrialRetriever,
build_patient_query`; see [API/data integration](docs/integrate-your-data.md).
Clinical heuristics are tailored to breast-cancer trial text; adaptations to
other diseases require validation, not just a change in the input data.

### 4. Develop a feature and submit a Pull Request

```bash
git switch main
git pull --ff-only
git switch -c feat/my-improvement
# edit code, tests and docs
python -m pytest -q
python scripts/smoke_test.py
git status --short
# inspect staged files before committing
git add libcat tests README.md    # adjust paths to your actual change
git commit -m "feat: describe the improvement"
git push -u origin feat/my-improvement
```

Open a Pull Request targeting `main`. Explain **what changed, why, how it was
tested, and any changes to research metrics**. The test workflow in
`.github/workflows/tests.yml` runs on PRs using Python 3.10 and 3.12.
Maintainers should review the changes and CI before merging. A collaborator can
be invited under repository **Settings → Collaborators and teams** after the
repository exists; GitHub records their commits and PRs as contributions.

### 5. Add large-data or neural evaluation only when you need it

```bash
python -m pip install -e ".[dense]"        # downloads model weights on first use
python scripts/download_trec_data.py --corpus  # optional multi-GB historical corpus
python scripts/parse_trec_corpus.py
python scripts/run_trec_eval.py --mode lexical  # full historical candidate set
```

**Do not commit datasets, model weights, credentials, or real patient records.**
`data/trec/` and generated `results/` are ignored by Git. Recheck with
`git status --short` before every push. Downloaded TREC data and model licenses
must be evaluated separately from this repository's source-code license.
See the [large data guide](docs/data-management.md) for authorized sources and
local paths.

New developers can start with an Issue for a parser edge case, a clearer
integration example, a retrieval unit test, a metric check, or UI accessibility.
For the full collaboration process see [CONTRIBUTING.md](CONTRIBUTING.md).

## Where this could go

The goal is to make LiBCaT a **configurable research framework for clinical-trial
retrieval experiments**, not to present the current prototype as a finished result.
The next practical improvements are (1) pluggable retrievers/rerankers and configurable
experiments, (2) reproducible TREC benchmark runs with documented ablations, and
(3) better support for user-provided corpora. More ambitious directions—such as
longitudinal trial updates, disease-specific adapters or clinical decision-support
research—would require substantial new validation, privacy safeguards and clinical
oversight. **None of these future capabilities is claimed to exist today.**

See **[ROADMAP.md](ROADMAP.md)** for candidate milestones, starter issues, and
acceptance criteria. Contributions are welcome via
[CONTRIBUTING.md](CONTRIBUTING.md).

## Reproducibility and limitations

- Heuristic score weights were developed in a research prototype; they are not calibrated
  probabilities and must not be treated as clinically validated.
- TREC qrels cover only judged pairs and are not a real-world eligibility oracle.
- The code is provided as-is; changing corpora or model versions may change results.
- CI verifies the offline lexical path; heavy model loading and full TREC evaluation
  require separate local validation and are not claimed as tested by CI.

## Troubleshooting package installation

If `pip` cannot fetch build dependencies from PyPI despite `setuptools>=68`
already being installed in the active virtual environment, you can avoid
temporary build isolation. First verify `python -m pip show setuptools wheel`,
then retry `python -m pip install --no-build-isolation -e ".[dev,web]"`.
This is a network/build-environment workaround, not a fix for missing runtime
dependencies.
